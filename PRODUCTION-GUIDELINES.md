## ⚠️ CRITICAL RULES

### 1. Production is READ-ONLY for Debugging Only

| Action | Allowed? | Reason |
|--------|----------|--------|
| Read logs | ✅ Yes | Debugging |
| Check git status | ✅ Yes | Debugging |
| Read files | ✅ Yes | Debugging |
| **Modify files** | ❌ NO | Use deployment |
| **Edit DB directly** | ❌ NO | Use migrations |
| **Run commands** | ❌ NO | Use deployment |
| **Install packages** | ❌ NO | Use deployment |

### 2. All Changes Go Through Deployment Pipeline

```
Local → Git Push → GitHub Actions → Deploy to Prod
```

**Never:**
- Edit files directly on server
- Run composer/npm install manually on server
- Modify database directly
- Change config files on server

### 3. SSH Access Purpose

SSH access is for:
- ✅ Debugging deployment issues
- ✅ Checking logs (`tail -f storage/logs/laravel.log`)
- ✅ Verifying file structure
- ✅ Emergency rollbacks (with explicit approval)

SSH access is NOT for:
- ❌ Development work
- ❌ Running tests
- ❌ Installing dependencies manually
- ❌ Modifying code

## Deployment Workflow

### Normal Deployment
```bash
# Local machine
git add -A
git commit -m "your message"
git push origin main
# GitHub Actions handles the rest
```

### Emergency Hotfix
```bash
# Option 1: Quick commit and deploy
git commit --allow-empty -m "hotfix: trigger deploy"
git push

# Option 2: Rollback (requires approval)
ssh -p 65002 u949031532@45.84.206.11
cd /home/u949031532/domains/seoindicator.com/public_html
git reset --hard HEAD~1
```

## Untracked Files on Production

Build artifacts (Next.js static export) will always show as untracked:

```
_next/
404.html
index.html
*.svg
etc.
```

These are **expected and intentional** - they're generated by the build and uploaded via SCP. They are ignored by `.gitignore` and should NOT be committed.

## Database Changes

### All DB Changes Use Migrations

```bash
# Create migration locally
cd backend
php artisan make:migration your_migration_name

# Edit the migration file
# Commit and push
# Deployment runs migrations automatically
```

### Never Modify DB Directly

- ❌ No direct SQL queries on production
- ❌ No manual table modifications
- ✅ Use Laravel migrations only
- ✅ Run via deployment pipeline

## Incident Response

### If Site Goes Down

1. **Check health:** `curl https://seoindicator.com/api/health`
2. **Check logs:** SSH and read `storage/logs/laravel.log`
3. **Check git status:** Ensure deployment completed
4. **Report findings** to user before taking action

### If Deployment Fails

1. Check GitHub Actions logs
2. SSH and verify state
3. Identify issue
4. Fix locally, push fix
