# SPECIFICATIONS Template

This folder contains technical specifications.

## Naming Convention
`SPEC-X.md` where X matches the related FEAT-X number.

## Specification File Structure

```markdown
# SPEC-X: [Feature Name] — Technical Specification

## STATUS
`Specification In Progress` | `To Break Into Tasks` | `Breaking Into Tasks` | `Cancelled`

## Overview
_Technical overview of the implementation_

## Requirements
- Functional requirements
- Non-functional requirements

## Technical Design
- Architecture
- Components
- Data flow
- API design

## Implementation Notes
_Key implementation details_

## Dependencies
_External services, libraries, or other features_

## Risks & Mitigations
_Potential issues and how to address them_

## Tasks
- [ ] SPEC-X-1: Task name
- [ ] SPEC-X-2: Task name

## Related
- Feature: FEAT-X
- Tests: TESTS/SPEC-X-*.md
```

---

## Valid Status Values & Agent Actions

| Status | Who | Action |
|--------|-----|--------|
| `Specification In Progress` | Architect | **Sets** after picking up feature |
| `To Break Into Tasks` | Architect | **Sets** when specification complete |
| `To Break Into Tasks` | SpecSystemAnalyst | **Picks up** for breakdown |
| `Breaking Into Tasks` | SpecSystemAnalyst | **Sets** while creating tasks |
| `Cancelled` | Any agent | Sets with documented reason |

---

## Workflow

```
Architect picks up FEAT-X ("New Feature")
         ↓
Architect creates SPEC-X ("Specification In Progress")
         ↓
Architect completes spec ("To Break Into Tasks")
         ↓
SpecSystemAnalyst picks up ("To Break Into Tasks")
         ↓
SpecSystemAnalyst creates TASKS ("Breaking Into Tasks")
         ↓
SpecSystemAnalyst sets tasks to "To Prioritize"
```
