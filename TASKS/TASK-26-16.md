## Description
Implement the ModelPricingService that manages AI model data, pricing calculations, and OpenRouter sync.

## Acceptance Criteria

### ModelPricingService Methods
- [ ] `getAvailableModels(): Collection` - Get all active models
- [ ] `getModelById(int $id): ?AIModel` - Get single model
- [ ] `getModelByProviderId(string $provider, string $modelId): ?AIModel`
- [ ] `getModelPricing(string $modelId): array` - Get pricing breakdown
- [ ] `calculateAnalysisCost(string $modelId, int $estimatedTokens): float`
- [ ] `syncModelsFromOpenRouter(): int` - Sync from OpenRouter API
- [ ] `getUserDefaultModel(User $user): ?AIModel` - Get user's preferred model
- [ ] `setUserDefaultModel(User $user, int $modelId): void`

### Pricing Calculation
- [ ] Based on input and output token costs
- [ ] Estimated tokens based on analysis type
- [ ] Different costs for different analysis types (quick vs deep)
- [ ] Round to 2 decimal places

### OpenRouter Sync
- [ ] Fetch models from `https://openrouter.ai/api/v1/models`
- [ ] Parse pricing data (input/output costs per 1M tokens)
- [ ] Parse context window sizes
- [ ] Parse capabilities (vision, tools, etc.)
- [ ] Update existing models or create new ones
- [ ] Deactivate models no longer available

### Default Model Logic
- [ ] User can set a default model
- [ ] Fall back to system default if none set
- [ ] Validate model is active before setting

### Caching
- [ ] Cache available models for 1 hour
- [ ] Invalidate cache after sync
- [ ] Cache user default model

### Unit Tests
- [ ] Test model listing
- [ ] Test pricing calculation accuracy
- [ ] Test OpenRouter sync (mocked)
- [ ] Test default model preference
- [ ] Test cache invalidation

- Rate limit sync operations

## Cost Estimation Formula
```
input_cost = (estimated_input_tokens / 1,000,000) * cost_per_1m_input
output_cost = (estimated_output_tokens / 1,000,000) * cost_per_1m_output
total_cost = input_cost + output_cost
```
