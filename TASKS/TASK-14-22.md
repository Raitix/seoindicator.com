### [2026-03-17 20:15 GMT+2] Developer: Fixing Infinite Loop Bug

**Root Cause Analysis:**

The infinite loop bug in `AuditDetailPage.tsx` was caused by the useEffect that updates the URL when filters change. The issue had multiple contributing factors:

1. **Dependency Array Problem:** The useEffect included `isLoading` and `error` in its dependency array. These values change during the data fetch cycle (isLoading: true → false), causing the effect to re-run unnecessarily.

2. **URL Update Chain:** When the effect runs after data loads, it updates the URL via `window.history.replaceState`. In some Next.js versions, URL changes can trigger `useSearchParams` to update, which causes `initialFilters` to be recomputed via `useMemo`.

3. **No Initial Mount Guard:** The effect ran on initial mount without checking if it was the first render, potentially causing issues with the initial URL state.

**Fix Applied:**

1. **Removed `isLoading` and `error` from dependency array** - The URL should only update when `filters`, `page`, or `perPage` change, not when data loading state changes.

2. **Added `hasMountedRef`** - Tracks whether the component has completed its initial mount. The effect skips URL updates on the first render to prevent unnecessary state changes.

3. **Improved `prevFilterKeyRef` usage** - Better tracking of filter state changes to detect actual user-initiated filter changes vs data updates.

**Files Modified:**
- `frontend/components/audit/AuditDetailPage.tsx` - Fixed useEffect infinite loop

**Code Changes:**
```javascript
// Before (problematic):
React.useEffect(() => {
  if (isLoading || error) { return; }
  // ... URL update logic
}, [filters, page, perPage, isLoading, error]); // ← isLoading/error cause re-runs

// After (fixed):
const hasMountedRef = React.useRef(false);
React.useEffect(() => {
  if (!hasMountedRef.current) {
    hasMountedRef.current = true;
    return; // Skip initial mount
  }
  // ... URL update logic
}, [filters, page, perPage]); // ← Only actual filter changes
```

1. The `setRef` function is called inside an `Array.map()` loop
2. Radix UI's internal ref management iterates over child elements and sets refs
3. Something is causing the refs to be unstable (changing on every render)
4. This triggers an infinite cascade of ref updates → re-renders

**Dependency Analysis:**
```json
{
  "radix-ui": "^1.4.3",  // Meta package
  "@radix-ui/react-select": "2.2.6",  // Transitive dependency
```

**Why This Is Problematic:**
1. React 19 changed how refs are handled (can pass as props without forwardRef)
2. Radix UI's internal ref management may not be fully compatible with React 19's ref changes
3. The `setRef` pattern with `Array.map` is common in Radix UI's collection management

1. **Update Radix UI to latest React 19 compatible versions:**
