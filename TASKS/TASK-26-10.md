## Description
Create REST API endpoint to receive and process Stripe webhook events for payment confirmation.

## Acceptance Criteria

### Endpoint
- [ ] `POST /api/v1/payments/stripe/webhook`
- [ ] NO authentication required (Stripe-signed)
- [ ] Returns 200 OK for successful processing

### Webhook Events Handled

#### payment_intent.succeeded
- [ ] Verify payment intent exists in our records
- [ ] Check idempotency (not already processed)
- [ ] Add credits to user balance via CreditService
- [ ] Update transaction status to completed
- [ ] Send confirmation email (optional)

#### payment_intent.payment_failed
- [ ] Log failure reason
- [ ] Update transaction status to failed
- [ ] Notify user (optional)

#### charge.refunded
- [ ] Verify refund amount
- [ ] Deduct credits from user balance (if applicable)
- [ ] Create refund transaction record

### Security Measures
- [ ] Verify Stripe signature using `STRIPE_WEBHOOK_SECRET`
- [ ] Reject requests with invalid/missing signature (401)
- [ ] Use timing-constant comparison for signature
- [ ] Log all webhook attempts

### Idempotency
- [ ] Check if payment_intent already processed
- [ ] Use database transaction with unique constraint
- [ ] Return 200 OK even for duplicate (idempotent)

### Response Format
- [ ] 200 OK for successful processing
- [ ] 400 Bad Request for malformed payload
- [ ] 401 Unauthorized for invalid signature
- [ ] 500 Internal Server Error for processing errors

### Controller Implementation
- [ ] `handleStripeWebhook()` method in PaymentController
- [ ] Calls StripeGatewayService->handleWebhook()
- [ ] Dispatches events for async processing (optional)
- [ ] Returns appropriate HTTP status

### Feature Tests
- [ ] Test successful payment confirmation
- [ ] Test idempotency (double processing prevention)
- [ ] Test invalid signature rejection
- [ ] Test payment failure handling
- [ ] Test refund handling
- [ ] Test malformed payload handling

## Notes
- Webhooks can arrive out of order
- Stripe retries webhooks until 200 received
- MUST be idempotent for reliability
- Consider queueing for heavy processing

## Security Considerations
- CRITICAL: Always verify webhook signature
- Never trust webhook payload without verification
- Log all webhook events for audit
- Time-sensitive: respond quickly (within 5s)

## Stripe Webhook Configuration
- Endpoint URL: `https://api.example.com/api/v1/payments/stripe/webhook`
- Events to listen: `payment_intent.*`, `charge.refunded`
