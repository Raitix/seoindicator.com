## Description

## Acceptance Criteria

- [ ] `AnalyticsAggregator` class created at `app/Services/AIVisibility/AnalyticsAggregator.php`

- [ ] `aggregate()` method implemented
  - [ ] Accepts: `projectId`, `period` (day, week, month)
  - [ ] Aggregates query results into `ai_mention_analytics` table
  - [ ] Calculates all metrics for each platform
  - [ ] Upserts record (unique constraint on project/platform/period)
  - [ ] Returns created/updated `AIMentionAnalytics` model

- [ ] `calculateMentionRate()` method implemented
  - [ ] Accepts: `projectId`, `platform`, `period`
  - [ ] Formula: `(brand_mentions / total_queries) * 100`
  - [ ] Returns decimal (0.00 - 100.00)
  - [ ] Returns 0.00 if no queries

- [ ] `calculateShareOfVoice()` method implemented
  - [ ] Accepts: `projectId`, `period`
  - [ ] Formula: `brand_mentions / (brand_mentions + sum(competitor_mentions)) * 100`
  - [ ] Returns decimal (0.00 - 100.00)
  - [ ] Handles division by zero (returns 0.00)

- [ ] `getTrend()` method implemented
  - [ ] Accepts: `projectId`
  - [ ] Compares current period vs previous period
  - [ ] Returns: `{ direction: up|down|stable, change_percent: float }`
  - [ ] Stable if change < 5%

- [ ] `getTopCategories()` method implemented
  - [ ] Accepts: `projectId`, `limit` (default: 5)
  - [ ] Groups queries by `query_category`
  - [ ] Returns array of `{ category, count, mention_rate }`
  - [ ] Sorted by count descending

- [ ] `getSentimentBreakdown()` method implemented
  - [ ] Accepts: `projectId`, `period`
  - [ ] Groups mentions by sentiment
  - [ ] Returns: `{ positive: int, neutral: int, negative: int, mixed: int }`
  - [ ] Calculates average sentiment score (-1.00 to +1.00)

- [ ] Performance optimization
  - [ ] Uses database aggregation queries (not PHP loops)
  - [ ] Caches results for 1 hour
  - [ ] Batch processing for large datasets

- [ ] Unit tests created
  - [ ] Test each calculation method
  - [ ] Test edge cases (zero queries, single mention)
  - [ ] Test caching behavior
  - [ ] Test period date calculations

### Bug Report

**Severity:** Critical (blocks all tests)

**Issue:** `AnalyticsAggregator` does not implement `AnalyticsAggregatorInterface` correctly.

| Method | Interface Signature | Implementation Signature |
|--------|---------------------|-------------------------|
| `getTrend()` | `getTrend(int $projectId, int $days = 90): array` | `getTrend(int $projectId, string $period = 'week'): array` |

**Error Message:**
```
PHP Fatal error: Declaration of App\Services\AIVisibility\AnalyticsAggregator::getTrend(int $projectId, string $period = 'week'): array must be compatible with App\Services\AIVisibility\Contracts\AnalyticsAggregatorInterface::getTrend(int $projectId, int $days = 90): array
```

### Root Cause Analysis

The Developer implemented two different trend methods:
1. `getTrend($projectId, $period)` - Period-based comparison (current vs previous week/month)
2. `getTrendAnalysis($projectId, $days)` - Days-based historical trend

But the interface only defines `getTrend(int $projectId, int $days = 90)` - which maps to the `getTrendAnalysis()` functionality.

### Fix Options

**Option A: Update implementation to match interface**
- Rename current `getTrend()` to `getPeriodTrend()` (internal method)
- Make `getTrend($projectId, int $days = 90)` return the historical trend data (matching `getTrendAnalysis()`)
- Update tests to expect the interface signature

**Option B: Update interface to match implementation**
- Change interface `getTrend(int $projectId, int $days)` to `getTrend(int $projectId, string $period)`
- Add `getTrendAnalysis(int $projectId, int $days)` to interface
- Update any code that depends on the current interface

**Recommendation:** Option A - tests should be updated to match the interface contract, as the interface was designed first.

### Tests Affected
All 45 tests in Category 5 (getTrend) - AA-131 to AA-175 expect `string $period` parameter but interface specifies `int $days`.
