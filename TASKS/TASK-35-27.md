## Description
Fix the production `GET /api/v1/sites/{siteId}/locations` endpoint so it returns the correct JSON auth/authorization/data response instead of a Laravel `500 Server Error` HTML page. This is currently blocking production validation of the Local SEO location-management page.

## Acceptance Criteria
- [ ] `GET /api/v1/sites/{siteId}/locations` no longer returns **500 HTML** in production.
- [ ] Unauthenticated requests return the correct protected-route response (expected JSON `401` unless product rules specify another JSON code).
- [ ] Authenticated requests for non-owned or missing sites return a correct JSON authorization/not-found response (`403`/`404` as intended), not a server error.
- [ ] Authenticated requests for an owned site return **200 JSON** with a normalized list payload (including the empty-state case).
- [ ] The frontend `/sites/{siteId}/local` page can load its real production list/empty/error UI from this endpoint.
- [ ] Automated coverage exists for the failing production scenario, including guest and cross-user access.
- [ ] If the failure is caused by production schema drift (for example around `business_locations` columns), the remediation is included in deployment notes/migrations.
