**Root Cause Analysis:**

The current architecture is **fundamentally broken** for the intended use case:

1. **Static Export Limitation:** With `output: 'export'` and `dynamicParams = false`, only `/audit/_/` is generated as static HTML
2. **Missing Dynamic Route Handling:** Actual audit hashes like `/audit/abc123.../` don't have corresponding HTML files
3. **Hostinger Returns Generic 404:** When the HTML file doesn't exist, Hostinger serves its default 404 page instead of Next.js's custom not-found page
4. **Client-Side Component Never Runs:** The `AuditPageClient.tsx` component can only run if the page loads, but it never loads for actual hashes

**Why the "fix" doesn't work:**
```
generateStaticParams() returns [{ hash: '_' }]  →  Only /audit/_/ is generated
dynamicParams = false                           →  No other hashes are allowed
Client-side component uses useParams()          →  Never runs for other hashes (404 first)
```
