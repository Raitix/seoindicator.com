## Description
Implement rate limiting and anti-abuse measures for the interactive tools. Prevents spam, abuse, and ensures fair usage of server resources.

---

## Acceptance Criteria
- [ ] Implement per-IP rate limiting (10 requests/minute)
- [ ] Add daily limit per IP (100 requests/day)
- [ ] Show CAPTCHA after 3 tool uses (unauthenticated users)
- [ ] Implement request throttling (max concurrent requests per IP)
- [ ] Add URL blocklist (localhost, internal IPs, file://)
- [ ] Log all tool requests for abuse monitoring
- [ ] Add rate limit headers to responses
- [ ] Create admin dashboard for rate limit monitoring
- [ ] Return proper 429 status with retry-after header
- [ ] Unit tests for rate limiting logic

## Technical Details

### Rate Limit Configuration
```typescript
const RATE_LIMITS = {
  perMinute: 10,
  perHour: 50,
  perDay: 100,
  captchaThreshold: 3
};
```

### Response Headers
```
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 7
X-RateLimit-Reset: 1709049600
Retry-After: 60
```

### 429 Response
```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "Too many requests. Please wait before trying again.",
    "retryAfter": 60
  }
}
```

### URL Blocklist
```typescript
const BLOCKED_PATTERNS = [
  /^localhost$/i,
  /^127\./,
  /^10\./,
  /^172\.(1[6-9]|2[0-9]|3[0-1])\./,
  /^192\.168\./,
  /^file:/i,
  /internal\./i
];
```

### CAPTCHA Integration
- Use hCaptcha (free tier available)
- Show after 3 unauthenticated tool uses
- Store CAPTCHA passed status in session
