# TASKS Template

This folder contains implementation tasks.

## Naming Convention
`SPEC-X-Y.md` where:
- X = Specification/Feature number
- Y = Task number within that specification

## Task File Structure

```markdown
# SPEC-X-Y: [Task Name]

## STATUS
`To Prioritize` | `Prioritization In Progress` | `To Write Tests` | `Tests Coverage In Progress` |
`To Develop` | `In Development` | `To Test Locally` | `Testing Locally` |
`To Deploy` | `In Deployment` | `To Test Prod` | `Testing Prod` |
`Done` | `Cancelled`

## PRIORITY
`High` | `Medium` | `Low`

## RISK
`Low` | `Medium` | `High`

## Related
- Feature: FEAT-X
- Specification: SPEC-X
- Test: TESTS/SPEC-X-Y.md

## Description
_What this task accomplishes_

## Acceptance Criteria
- [ ] Criterion 1
- [ ] Criterion 2

## Implementation Notes
_Technical details, approach_

## Dependencies
_Other tasks or external factors_

## Notes
_Additional context_

---

## Comments
_Agent communication log_

### [YYYY-MM-DD HH:MM] Agent: [Name]
_[Comment or note from agent]_

### [YYYY-MM-DD HH:MM] Agent: [Name]
_[Comment or note from agent]_
```

## Valid Status Values & Agent Actions

| Status | Who | Action |
|--------|-----|--------|
| `To Prioritize` | SpecSystemAnalyst | **Sets** after creating tasks |
| `To Prioritize` | ProjectManager | **Picks up** for prioritization |
| `Prioritization In Progress` | ProjectManager | **Sets** while prioritizing |
| `To Write Tests` | ProjectManager | **Sets** after prioritization |
| `To Write Tests` | PreTester | **Picks up** for test design |
| `Tests Coverage In Progress` | PreTester | **Sets** while writing tests |
| `To Develop` | PreTester | **Sets** when tests complete |
| `To Develop` | Developer | **Picks up** for implementation |
| `In Development` | Developer | **Sets** while implementing |
| `To Test Locally` | Developer | **Sets** when implementation complete |
| `To Test Locally` | LocalTester | **Picks up** for local testing |
| `Testing Locally` | LocalTester | **Sets** while testing |
| `To Deploy` | LocalTester | **Sets** when local tests pass |
| `To Deploy` | DevOps | **Picks up** for deployment |
| `In Deployment` | DevOps | **Sets** while deploying |
| `To Test Prod` | DevOps | **Sets** when deployed |
| `To Test Prod` | ProdTester | **Picks up** for prod testing |
| `Testing Prod` | ProdTester | **Sets** while testing |
| `Done` | ProdTester | **Sets** when prod tests pass |
| `Cancelled` | Any agent | Sets with documented reason |

---

## Communication
Agents leave comments in the **Comments** section for:
- Handoff notes to next agent
- Bug reports (LocalTester → Developer)
- Deployment notes (DevOps)
- Test results (LocalTester, ProdTester)
- Questions and clarifications

---

## Workflow

```
SpecSystemAnalyst creates TASK ("To Prioritize")
         ↓
ProjectManager picks up ("To Prioritize")
         ↓
ProjectManager prioritizes ("Prioritization In Progress" → "To Write Tests")
         ↓
PreTester picks up ("To Write Tests")
         ↓
PreTester writes tests ("Tests Coverage In Progress" → "To Develop")
         ↓
Developer picks up ("To Develop")
         ↓
Developer implements ("In Development" → "To Test Locally")
         ↓
LocalTester picks up ("To Test Locally")
         ↓
LocalTester tests ("Testing Locally" → "To Deploy" or back to Developer)
         ↓
DevOps picks up ("To Deploy")
         ↓
DevOps deploys ("In Deployment" → "To Test Prod")
         ↓
ProdTester picks up ("To Test Prod")
         ↓
ProdTester tests ("Testing Prod" → "Done" or back to Developer)
         ↓
DocSystemAnalyst updates documentation
```
