```php
Schema::create('payment_methods', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->onDelete('cascade');
    $table->string('stripe_customer_id'); // cus_...
    $table->string('stripe_payment_method_id')->nullable(); // pm_...
    $table->string('provider')->default('stripe');
    $table->string('brand')->nullable(); // visa, mastercard
    $table->string('last_four', 4)->nullable();
    $table->integer('exp_month')->nullable();
    $table->integer('exp_year')->nullable();
    $table->boolean('is_default')->default(false);
    $table->timestamps();

    $table->unique(['user_id', 'stripe_payment_method_id']);
    $table->index('stripe_customer_id');
});
```

**One Test Issue (PM-SEC-04):**
The test `test_no_sql_injection_via_payment_method_id` has a design flaw:
- It checks `PaymentMethod::count() > 0` to verify the table exists
- But the table is empty during the test, so count returns 0
- SQL injection protection works correctly (returns 404 due to route constraint `->where('id', '[0-9]+')`)
- The test should use `Schema::hasTable('payment_methods')` or create a record first
- This is a test design issue, not an implementation issue

**Implementation Notes:**
1. Used hard delete (not soft delete) as per original design - payment methods are references only, no sensitive data
2. Route constraint `->where('id', '[0-9]+')` prevents SQL injection and non-numeric IDs
3. StripeGatewayService is mockable via Laravel's service container
4. Default payment method logic: reassigns to next available when deleting default
5. Cannot delete the only payment method if it's default (returns 422)
