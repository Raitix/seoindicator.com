## Description
Create REST API endpoint to receive and process PayPal webhook events for payment confirmation.

## Acceptance Criteria

### Endpoint
- [ ] `POST /api/v1/payments/paypal/webhook`
- [ ] NO authentication required (PayPal-signed)
- [ ] Returns 200 OK for successful processing

### Webhook Events Handled

#### CHECKOUT.ORDER.APPROVED
- [ ] Verify order exists in our records
- [ ] Order is ready for capture
- [ ] Optionally auto-capture or notify user

#### PAYMENT.CAPTURE.COMPLETED
- [ ] Verify capture exists in our records
- [ ] Check idempotency (not already processed)
- [ ] Add credits to user balance via CreditService
- [ ] Update transaction status to completed
- [ ] Send confirmation email (optional)

#### PAYMENT.CAPTURE.DENIED
- [ ] Log denial reason
- [ ] Update transaction status to failed
- [ ] Notify user (optional)

#### PAYMENT.CAPTURE.REFUNDED
- [ ] Verify refund amount
- [ ] Deduct credits from user balance (if applicable)
- [ ] Create refund transaction record

### Security Measures
- [ ] Verify PayPal webhook signature via headers
- [ ] Validate webhook ID matches configured
- [ ] Use certificate validation
- [ ] Log all webhook attempts

### Idempotency
- [ ] Check if order/capture already processed
- [ ] Use database transaction with unique constraint
- [ ] Return 200 OK even for duplicate (idempotent)

### Response Format
- [ ] 200 OK for successful processing
- [ ] 400 Bad Request for malformed payload
- [ ] 401 Unauthorized for invalid signature
- [ ] 500 Internal Server Error for processing errors

### Controller Implementation
- [ ] `handlePayPalWebhook()` method in PaymentController
- [ ] Calls PayPalGatewayService->handleWebhook()
- [ ] Returns appropriate HTTP status

### Feature Tests
- [ ] Test successful payment capture
- [ ] Test idempotency (double processing prevention)
- [ ] Test invalid signature rejection
- [ ] Test payment denial handling
- [ ] Test refund handling
- [ ] Test malformed payload handling
