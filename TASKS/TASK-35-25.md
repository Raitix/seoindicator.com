# TASK-35-25: Fix Production API Routing for Authenticated Local SEO Flow

## STATUS
`To Deploy`

## SPECIFICATION
SPEC-035: Local SEO & Google Business Profile Tracking

## PRIORITY
`High`

## RISK
`Medium`

## Description
Fix the production routing/configuration mismatch that currently breaks the authenticated Local SEO flow. The deployed frontend is reachable at `/login`, `/register`, and `/sites/{siteId}/local`, but the same-origin API endpoints used by the app (`/api/v1/...`) return Hostinger's generic 404 HTML page instead of backend JSON responses. This blocks authentication and prevents real production validation of location management.

## Acceptance Criteria
- [ ] Production auth endpoints used by the frontend are reachable from the deployed app (same-origin proxy or correct absolute API origin).
- [ ] `GET /api/v1/auth/user` returns a backend JSON response (for unauthenticated requests, expected 401 JSON is acceptable) rather than Hostinger's generic 404 HTML page.
- [ ] `POST /api/v1/auth/register` and `POST /api/v1/auth/login` reach the backend and return backend JSON/validation/auth responses rather than generic 404 HTML.
- [ ] `GET /api/v1/sites/{siteId}/locations` reaches the backend and returns a backend JSON response (401/403/404/200 as appropriate), not generic 404 HTML.
- [ ] The production frontend can establish a real authenticated session and load `/sites/{siteId}/local`.
- [ ] TASK-35-17 can then be re-run successfully in production, including add/edit/delete and the `?locationId=` details dialog flow.
- [ ] Deployment/configuration notes are updated if the frontend API origin/proxy assumption changes.

## Dependencies
- TASK-35-13 (Business Location API Controller)
- TASK-35-17 (Location Management Page)

## Effort Estimate
3 hours

## Technical Notes
- Frontend code currently hardcodes same-origin `"/api/v1"` in auth and location hooks.
- If production uses a separate backend origin, the frontend needs an explicit runtime/base-URL strategy.
- If production expects same-origin `/api/v1`, Hostinger/LiteSpeed routing or reverse-proxy configuration must be restored so backend JSON responses are reachable.
- Re-test with both browser-based auth flow and direct HTTP checks after the fix.
