# Production Test Results Directory

This directory contains failed test logs from GitHub Actions CI runs against the production site.

## Structure

- `production_failed_tests_YYYYMMDD_HHMMSS_COMMIT.md` - Timestamped production test failure reports
- Each file contains:
  - Production deployment summary
  - Failed test details
  - Error logs (if any)
  - Next steps for debugging

## Usage

When production tests fail in CI, a new log file will be automatically created here with:
- **Date and time** of the failure
- **Commit hash** that caused the failure
- **Branch name** where the failure occurred
- **Production URL** being tested
- **Detailed error information**
- **Screenshots and traces** (referenced in the log)

## Manual Cleanup

You can safely delete old log files to keep the repository clean. Consider keeping logs for:
- Recent failures (last 30 days)
- Critical failures that need investigation
- Failures related to ongoing development

## Integration

These logs are automatically generated by the GitHub Actions workflow and provide a convenient way to:
- Track production test failures over time
- Debug issues without downloading artifacts
- Share failure information with team members
- Maintain a history of production test reliability
