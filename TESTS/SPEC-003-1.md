## Test Cases

### Test 1: Migration Creates Competitors Table
- **Type:** Feature/Integration
- **Description:** Verify competitors table is created with correct schema
- **Preconditions:** Database connection established, users table exists
- **Steps:**
  1. Run migration
  2. Check table exists
  3. Verify columns: id, user_id, domain, display_name, notes, created_at, updated_at
- **Expected Result:** Table created with all required columns
- **Edge Cases:** 
  - Running migration twice (should not fail)
  - Column data types and defaults

### Test 2: Migration Creates Competitor Rankings Table
- **Type:** Feature/Integration
- **Description:** Verify competitor_rankings table is created with correct schema
- **Preconditions:** Database connection established, competitors and keywords tables exist
- **Steps:**
  1. Run migration
  2. Check table exists
  3. Verify columns: id, competitor_id, keyword_id, position, url, checked_at
- **Expected Result:** Table created with all required columns
- **Edge Cases:**
  - position and url can be null (not ranking)

### Test 3: Foreign Key Constraints - Competitors to Users
- **Type:** Feature/Integration
- **Description:** Verify foreign key from competitors.user_id to users.id
- **Preconditions:** users table exists
- **Steps:**
  1. Attempt to insert competitor with non-existent user_id
  2. Verify database rejects insert
  3. Insert user, then competitor with valid user_id
  4. Delete user, verify competitor is cascade deleted
- **Expected Result:** Foreign key constraint enforces referential integrity
- **Edge Cases:**
  - Cascade delete behavior
  - NULL user_id (should not be allowed)

### Test 4: Foreign Key Constraints - Rankings to Competitors
- **Type:** Feature/Integration
- **Description:** Verify foreign key from competitor_rankings.competitor_id to competitors.id
- **Preconditions:** users, keywords, competitors tables exist
- **Steps:**
  1. Attempt to insert ranking with non-existent competitor_id
  2. Verify database rejects insert
  3. Create competitor, then ranking with valid competitor_id
  4. Delete competitor, verify ranking is cascade deleted
- **Expected Result:** Foreign key constraint enforces referential integrity

### Test 5: Foreign Key Constraints - Rankings to Keywords

### Test 6: Unique Constraint - User + Domain
- **Type:** Feature/Integration
- **Description:** Verify unique constraint on (user_id, domain) in competitors table
- **Preconditions:** users table exists, competitors table created
- **Steps:**
  1. Create competitor with user_id=1, domain='example.com'
  2. Attempt to create second competitor with same user_id and domain
  3. Verify database rejects duplicate
  4. Create competitor with same domain but different user_id
  5. Verify this is allowed
- **Expected Result:** Unique constraint prevents duplicate user+domain combinations
- **Edge Cases:**
  - Case sensitivity (domain should be case-insensitive)
  - Domain normalization (trailing slashes, www prefix)

### Test 7: Unique Constraint - Competitor + Keyword + Date
