## Notes for Developer

### Implementation Priority
1. **CrawlQueueService** - Core queue operations first
2. **LinkExtractorService** - HTML parsing and normalization
3. **DuplicateDetector** - Bloom filter or set implementation
4. **QueueConcurrency** - Lock management

### Database Considerations
- May need `crawl_queue` table migration if not using Redis
- Consider adding indexes on `crawl_job_id`, `status`, `priority`

### Redis vs Database Queue
- Redis recommended for high-performance (optional)
- Database queue acceptable for MVP
- Service should be agnostic to backing store

### Bloom Filter Configuration
- Size: ~1M bits for 100K URLs
- Hash functions: 7 for 1% false positive rate
- Can use `phpbloomfilter` or implement custom
