# TEST-35-25 — Production API Routing for Authenticated Local SEO Flow

## Task Reference
- Task: `TASK-35-25`
- Spec: `SPEC-035` — Local SEO & Google Business Profile Tracking
- Stage: LocalTester
- Status after local validation: `To Deploy`

## Overview
Production Local SEO is blocked because the deployed static frontend reaches `/login`, `/register`, and `/sites/{siteId}/local`, but same-origin `/api/v1/...` requests return Hostinger/LiteSpeed generic 404 HTML instead of backend JSON.

This test pack turns that production-only failure into deterministic frontend coverage:
- API base URL normalization for static deployments
- Sanctum CSRF origin resolution
- Auth requests hitting the configured backend origin
- Local SEO location hooks hitting the configured backend origin
- GBP connect flow hitting the configured backend origin

## Root Cause Captured by Tests
The current frontend contains hardcoded `"/api/v1"` and `"/sanctum/csrf-cookie"` assumptions in critical authenticated Local SEO paths. That works only if the static frontend host also proxies the backend.

Because `frontend/next.config.ts` uses `output: 'export'`, the app is deployed as a static export and cannot rely on Next.js runtime rewrites. The fix therefore needs an explicit, normalized runtime API-origin strategy (or equivalent host-level proxy that preserves the same contract).
