# Test Documentation: SPEC-SEC-2026-02-21-3 — Deploy Endpoint Rate Limiting

## Overview
Tests to verify rate limiting middleware on deploy endpoints and logging of failed authentication attempts.

## Test Type
- **Primary:** Integration Tests
- **Secondary:** API Tests

---

## Test Scenarios

### 1. Rate Limiting Applied to Deploy Endpoints

**Test ID:** SEC-3.1  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify deploy endpoints have rate limiting middleware.

**Preconditions:**
- Routes `/deploy/migrate` and `/deploy/rollback` exist

**Test Steps:**
1. Send 6 requests to `/deploy/migrate` within 15 minutes
2. Verify 6th request returns 429 Too Many Requests
3. Wait for rate limit window to expire
4. Verify requests work again

**Expected Result:**
- First 5 requests succeed (or fail with proper auth error)
- 6th request returns HTTP 429
- Response includes `Retry-After` header

**Rate Limit:** `throttle:5,15` (5 requests per 15 minutes)

---

### 2. Rate Limiting on Rollback Endpoint

**Test ID:** SEC-3.2  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify `/deploy/rollback` has independent rate limiting.

**Preconditions:**
- Route exists

**Test Steps:**
1. Exhaust rate limit on `/deploy/migrate`
2. Verify `/deploy/rollback` still accessible
3. Exhaust rate limit on `/deploy/rollback`
4. Verify 429 response

**Expected Result:**
- Each endpoint has independent rate limit
- Rate limits do not share counters

---

### 3. Failed Auth Logging

**Test ID:** SEC-3.3  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify failed authentication attempts are logged with required details.

**Preconditions:**
- Deploy endpoint requires authentication

**Test Steps:**
1. Send request with invalid auth token
2. Check log file for entry
3. Verify log contains:
   - IP address
   - User-Agent
   - Timestamp
   - Endpoint
   - Error type

**Expected Result:**
```
[2026-02-26 14:00:00] security.WARNING: Failed deploy auth {"ip":"192.168.1.1","user_agent":"curl/7.68.0","endpoint":"/deploy/migrate","error":"invalid_token"}
```

---

### 4. Rate Limiter Registered

**Test ID:** SEC-3.4  
**Type:** Unit  
**Priority:** High

**Description:** Verify rate limiter is properly registered in Laravel.

**Preconditions:**
- Laravel application configured

**Test Steps:**
1. Check `RouteServiceProvider::boot()` or `Kernel.php`
2. Verify `RateLimiter::for('deploy')` exists
3. Verify rate limit returns `Limit::perMinutes(15, 5)`

**Expected Result:**
```php
RateLimiter::for('deploy', function (Request $request) {
    return Limit::perMinutes(15, 5)->by($request->ip());
});
```

---

### 5. Rate Limit by IP (Not User)

**Test ID:** SEC-3.5  
**Type:** Integration  
**Priority:** High

**Description:** Verify rate limiting is by IP address, allowing legitimate users through.

**Preconditions:**
- Multiple IPs available for testing

**Test Steps:**
1. Exhaust rate limit from IP A
2. Verify IP B can still make requests
3. Verify IP A blocked until window expires

**Expected Result:**
- Rate limit applies per IP
- Different IPs have separate counters

---

### 6. Successful Auth Not Rate Limited Aggressively

**Test ID:** SEC-3.6  
**Type:** Integration  
**Priority:** Medium

**Description:** Verify successful authentication doesn't count heavily against rate limit.

**Preconditions:**
- Valid auth token available

**Test Steps:**
1. Send 5 successful requests
2. Verify 6th request still works (or has higher limit)

**Note:** This depends on implementation. May use same limit or separate.

---

### 7. Brute Force Protection

**Test ID:** SEC-3.7  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify brute force attack is mitigated.

**Preconditions:**
- None

**Test Steps:**
1. Send 50 rapid requests with various tokens
2. Verify IP is blocked after threshold
3. Verify lockout duration

**Expected Result:**
- Attacker IP blocked after threshold
- Legitimate IPs unaffected
