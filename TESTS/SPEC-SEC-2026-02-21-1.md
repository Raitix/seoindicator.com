# TESTS: SPEC-SEC-2026-02-21-1

## Purpose
To validate that no hardcoded secrets (e.g., APP_KEY, DB_PASSWORD, OAuth keys) exist in tracked files, and that sensitive data is appropriately managed through environment variables and placeholders.

---

## Test Scenarios

### 1. Ensure `.env` is not tracked in Git

**Steps:**
1. Verify `.env` is listed in `.gitignore`
2. Attempt to `git add .env` and ensure it's ignored

**Pass Criteria:**
- `.env` is ignored by Git and cannot be accidentally committed

---

### 2. Validate `.env.example` Structure

**Steps:**
1. Verify `.env.example` contains placeholders for all required secrets:
   - APP_KEY
   - DB_PASSWORD
   - OAuth credentials (GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET)
2. Ensure each placeholder has a clear description

**Pass Criteria:**
- Placeholders exist for all secrets
- Descriptions match task specification

---

### 3. Check for Hardcoded Secrets in Files

**Steps:**
1. Use the following commands to search for potential secrets:
   - `grep -r "APP_KEY=" . --include="*.env" --include="*.yml"`
   - `git grep "DB_PASSWORD="`
2. Validate no sensitive values exist (placeholders only).

**Pass Criteria:**
- No secrets (actual values) present in tracked files

---

### 4. Verify Git History for Exposed Secrets

**Steps:**
1. Use the following commands to check history:
   - `git log --all --full-history -- "**/.env"`
   - `git log --all -S"APP_KEY="`
2. Ensure secrets were purged from history (or are placeholders).

**Pass Criteria:**
- Git history contains no sensitive values

---

### 5. Validate Laravel Configuration

**Steps:**
1. Check `backend/.env` for placeholders instead of values
2. Ensure `APP_KEY` is dynamically populated via environment variable in GitHub Actions workflow

**Pass Criteria:**
- `backend/.env` has placeholders only
- GitHub Secrets integration is configured for `LARAVEL_APP_KEY`
