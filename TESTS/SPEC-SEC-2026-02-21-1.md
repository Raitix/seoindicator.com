# Test Documentation: SPEC-SEC-2026-02-21-1 — Remove Hardcoded Secrets

## Overview
Tests to verify that no hardcoded secrets exist in tracked files and that `.env` configuration is secure.

## Test Type
- **Primary:** Integration Tests (repository scanning)
- **Secondary:** Unit Tests (configuration validation)

---

## Test Scenarios

### 1. No Secrets in Tracked Files

**Test ID:** SEC-1.1  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify no secrets exist in any tracked file in the repository.

**Preconditions:**
- Repository is initialized
- All files are tracked

**Test Steps:**
1. Run `git grep -i "APP_KEY=base64:" -- '*.php' '*.env*' '*.yml' '*.yaml' '*.json'`
2. Run `git grep -i "DB_PASSWORD=" -- '*.php' '*.env*' '*.yml' '*.yaml'`
3. Run `git grep -i "GOOGLE_CLIENT_SECRET=" -- '*.php' '*.env*' '*.yml' '*.yaml'`
4. Run `git grep -i "GITHUB_CLIENT_SECRET=" -- '*.php' '*.env*' '*.yml' '*.yaml'`
5. Run `git grep -E "(password|secret|key|token).*=.*['\"][a-zA-Z0-9]{20,}['\"]" -- '*.php'`

**Expected Result:**
- All grep commands return empty (no matches)
- No file contains actual secret values

**Edge Cases:**
- False positives from test fixtures with dummy values
- Comments mentioning "secret" in documentation

---

### 2. .env.example Contains Placeholders Only

**Test ID:** SEC-1.2  
**Type:** Unit  
**Priority:** Critical

**Description:** Verify `.env.example` contains only placeholder values, not real secrets.

**Preconditions:**
- `.env.example` file exists

**Test Steps:**
1. Read `.env.example` file
2. Check each line for secret patterns
3. Verify no base64-encoded APP_KEY
4. Verify no real passwords

**Expected Result:**
```
APP_KEY=                    # Empty or placeholder
DB_PASSWORD=your_db_password
GOOGLE_CLIENT_SECRET=your_google_secret
```

---

### 3. .env is in .gitignore

**Test ID:** SEC-1.3  
**Type:** Unit  
**Priority:** Critical

**Description:** Verify `.env` is properly ignored by git.

**Preconditions:**
- `.gitignore` file exists

**Test Steps:**
1. Read `.gitignore` file
2. Check if `.env` is listed
3. Run `git check-ignore .env`

**Expected Result:**
- `.env` is in `.gitignore`
- `git check-ignore .env` returns exit code 0

---

### 4. Sensitive Files Not Tracked

**Test ID:** SEC-1.4  
**Type:** Integration  
**Priority:** Critical

**Description:** Verify sensitive files are not tracked in git.

**Preconditions:**
- Repository has commits

**Test Steps:**
1. Run `git ls-files | grep -E '\.env$|\.pem$|\.key$|credentials'`
2. Verify no matches

**Expected Result:**
- Command returns empty (no tracked sensitive files)

---

### 5. Config Files Use env() Helper

**Test ID:** SEC-1.5  
**Type:** Unit  
**Priority:** High

**Description:** Verify Laravel config files use `env()` helper instead of hardcoded values.

**Preconditions:**
- Laravel config files exist

**Test Steps:**
1. Scan `config/*.php` files
2. Check for `env('APP_KEY')`, `env('DB_PASSWORD')`, etc.
3. Verify no hardcoded secrets in config

**Expected Result:**
- All secret references use `env()` helper
- No hardcoded passwords or keys

## Security Considerations

### Adversarial Testing
- Test that adding a secret to a file fails CI
- Test that `.env.backup` is also ignored
- Test for common secret patterns (AWS keys, JWT secrets)

### False Positive Handling
- Allow test fixtures with `test_secret` or `dummy_key` patterns
- Skip files in `tests/fixtures/` directory
