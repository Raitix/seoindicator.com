## API Endpoints

| Method | Endpoint | Purpose | Auth |
|--------|----------|---------|------|
| GET | `/api/v1/locations/{id}/rankings` | Current rankings for location's keywords | Required |
| GET | `/api/v1/locations/{id}/rankings/history` | Historical ranking data | Required |
| POST | `/api/v1/locations/{id}/rankings/check` | Trigger ranking check (all keywords) | Required |
| POST | `/api/v1/locations/{id}/rankings/check/{keywordId}` | Trigger single keyword check | Required |
| GET | `/api/v1/locations/{id}/rankings/quota` | Monthly quota usage | Required |
| GET | `/api/v1/locations/{id}/competitors` | List tracked competitors | Required |
| POST | `/api/v1/locations/{id}/competitors` | Add competitor for tracking | Required |
| DELETE | `/api/v1/locations/{id}/competitors/{competitorId}` | Remove competitor | Required |

## Notes for Developer

### Implementation Order

1. **Controller Methods:** Implement in route order (GET rankings → GET history → POST check → etc.)
2. **Form Requests:** Create validation classes for POST endpoints
3. **Policies:** Create LocalRankingPolicy for authorization
4. **Service Integration:** Inject LocalRankService interface

### Key Considerations

1. **Quota Enforcement:** All check endpoints must enforce 50/month limit
2. **Job Queue:** Check endpoints should dispatch jobs, not run synchronously
3. **Rate Limiting:** Apply `throttle:60,1` middleware
4. **Response Format:** Use `success`, `data`, `error` structure

### Response Codes Reference

| Code | When to Use |
|------|-------------|
| 200 | GET success |
| 201 | POST create success |
| 202 | POST accepted (async job) |
| 204 | DELETE success |
| 401 | Unauthenticated |
| 403 | Forbidden (policy denial) |
| 404 | Resource not found |
| 422 | Validation error |
| 429 | Quota exceeded |
| 500 | Server error |
