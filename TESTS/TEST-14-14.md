## API Endpoints Tested

### 1. List Issues for Audit
```
GET /api/v1/audits/{auditId}/issues
```

**Query Parameters:**
- `severity` - Filter by severity (critical, warning, notice)
- `status` - Filter by status (open, fixed, ignored)
- `category` - Filter by issue category
- `search` - Search in URL or description
- `sort_by` - Sort field (created_at, severity, url)
- `sort_order` - Sort direction (asc, desc)
- `per_page` - Items per page (default: 25, max: 100)
- `page` - Page number

**Response (200):**
```json
{
    "success": true,
    "data": [
        {
            "id": 1,
            "url": "https://example.com/page",
            "issue_type": {
                "id": 1,
                "name": "Missing title tag",
                "category": "meta"
            },
            "severity": "critical",
            "description": "This page is missing a title tag",
            "recommendation": "Add a unique, descriptive title tag to this page.",
            "status": "open",
            "created_at": "2026-03-06T15:05:00Z"
        }
    ],
    "meta": {
        "current_page": 1,
        "per_page": 25,
        "total": 50,
        "severity_counts": {
            "critical": 10,
            "warning": 25,
            "notice": 15
        },
        "status_counts": {
            "open": 45,
            "fixed": 3,
            "ignored": 2
        }
    }
}
```

### 3. Update Issue Status
```
PATCH /api/v1/issues/{issueId}
```

**Request:**
```json
{
    "status": "fixed"
}
```

**Response (200):**
```json
{
    "success": true,
    "data": {
        "id": 1,
        "status": "fixed",
        "updated_at": "2026-03-06T16:00:00Z"

```

### 4. Bulk Update Issues
```
PATCH /api/v1/audits/{auditId}/issues/bulk
```

**Request:**
```json
{
    "issue_ids": [1, 2, 3, 4, 5],
    "status": "ignored"
}
```

**Response (200):**
```json
{
    "success": true,
    "data": {
        "updated_count": 5,
        "message": "5 issues marked as ignored"
    }
}
```

## Request Validation Rules

### UpdateIssueStatusRequest
| Field | Rules |
|-------|-------|
| `status` | Required, in:open,fixed,ignored |

### BulkUpdateIssuesRequest
| Field | Rules |
|-------|-------|
| `issue_ids` | Required, array, max:100 |
| `issue_ids.*` | Integer, exists:audit_issues,id |
| `status` | Required, in:open,fixed,ignored |

## Authorization Rules

| Endpoint | Authorization |
|----------|---------------|
| List Issues | User must own the site associated with the audit |
| Get Issue | User must own the site associated with the issue's audit |
| Update Issue | User must own the site AND audit must be completed |
| Bulk Update | User must own the site AND audit must be completed |

## Business Rules

1. **Completed Audit Required:** Issues can only be updated for audits with status `completed`
2. **Bulk Update Limit:** Maximum 100 issues per bulk update request
3. **Audit-Scoped Bulk:** Bulk update only affects issues belonging to the specified audit
4. **Status Transition:** All status transitions are allowed (open ↔ fixed ↔ ignored)

## Security Implementation

| Measure | Implementation |
|---------|---------------|
| SQL Injection | Parameterized queries via Eloquent |
| XSS Protection | Laravel response encoding |
| IDOR Prevention | User ownership verification |
| Authorization | Site.user_id === Auth::user()->id |
