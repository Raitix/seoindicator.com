## Test Scenarios

### WSG-001: Valid Webhook Signature Verification
**Scenario:** Valid Stripe signature is accepted
**Input:**
```json
{
  "stripe_signature": "t=1234567890,v1=abc123...",
  "payload": {"id": "evt_123", "type": "payment_intent.succeeded", "data": {...}}
}
```
**Expected Output:**
- HTTP 200 OK
- Event processed successfully
- Credits added to user balance

### WSG-002: Invalid Webhook Signature Rejection
**Scenario:** Invalid signature returns 401
**Input:**
```json
{
  "stripe_signature": "t=1234567890,v1=invalid...",
  "payload": {"id": "evt_123", "type": "payment_intent.succeeded", "data": {...}}
}
```
**Expected Output:**
- HTTP 401 Unauthorized
- No processing occurs
- Log entry for invalid signature

### WSG-003: Missing Webhook Signature
**Scenario:** Missing signature header returns 401
**Input:**
```json
{
  "stripe_signature": null,
  "payload": {"id": "evt_123", "type": "payment_intent.succeeded", "data": {...}}
}
```
**Expected Output:**
- HTTP 401 Unauthorized
- Log entry for missing signature

### WSG-004: Malformed Payload
**Scenario:** Invalid JSON payload returns 400
**Input:**
```json
{
  "stripe_signature": "valid_sig",
  "payload": "not valid json"
}
```
**Expected Output:**
- HTTP 400 Bad Request
- Log entry for malformed payload

### WSG-005: payment_intent.succeeded Event
**Scenario:** Successful payment adds credits
**Input:**
```json
{
  "id": "evt_123",
  "type": "payment_intent.succeeded",
  "data": {
    "object": {
      "id": "pi_abc123",
      "amount": 5000,
      "currency": "usd",
      "metadata": {"user_id": "1", "package_id": "starter"}
    }
  }
}
```
**Expected Output:**
- HTTP 200 OK
- CreditService::addCredits called with amount=50.00
- Transaction status updated to 'completed'
- User balance increased by $50.00

### WSG-006: payment_intent.payment_failed Event
**Scenario:** Failed payment logs failure
**Input:**
```json
{
  "id": "evt_124",
  "type": "payment_intent.payment_failed",
  "data": {
    "object": {
      "id": "pi_failed",
      "last_payment_error": {"message": "Card declined"},
      "metadata": {"user_id": "1"}
    }
  }
}
```
**Expected Output:**
- HTTP 200 OK
- Transaction status updated to 'failed'
- Failure reason logged
- No credits added

### WSG-007: charge.refunded Event
**Scenario:** Refund deducts credits
**Input:**
```json
{
  "id": "evt_125",
  "type": "charge.refunded",
  "data": {
    "object": {
      "id": "ch_abc123",
      "payment_intent": "pi_abc123",
      "amount_refunded": 2500,
      "refunds": {"data": [{"id": "re_123"}]}
    }
  }
}
**Expected Output:**
- HTTP 200 OK
- CreditService::deductCredits called if user has sufficient balance
- Refund transaction record created
- User balance decreased by refund amount

### WSG-008: Idempotency - Duplicate Event Processing
**Scenario:** Same event processed twice returns 200 both times
**Input:**
```json
{
  "id": "evt_123",
  "type": "payment_intent.succeeded",
  "data": {...}
}
```
**Expected Output (first call):**
- HTTP 200 OK
- Credits added
- Transaction created

**Expected Output (second call):**
- HTTP 200 OK (idempotent response)
- No duplicate credits added
- No duplicate transaction created

### WSG-009: Unknown Event Type
**Scenario:** Unknown event type returns 200 (acknowledged but not processed)
**Input:**
```json
{
  "id": "evt_126",
  "type": "customer.updated",
  "data": {...}
}
```
**Expected Output:**
- HTTP 200 OK
- Event logged as unhandled
- No processing occurs

### WSG-010: Expired Signature Timestamp
**Scenario:** Old signature timestamp is rejected
**Input:**
```json
{
  "stripe_signature": "t=1000000000,v1=abc123...",
  "payload": {...}
}
```
**Expected Output:**
- HTTP 401 Unauthorized
- Log entry for expired timestamp

### WSG-011: Replay Attack Prevention
**Scenario:** Same signature used twice within tolerance
**Input:**
```json
{
  "stripe_signature": "t=<current_time>,v1=valid_sig",
  "payload": {...}
}
```
**Expected Output:**
- Both requests processed normally
- Idempotency handled at event ID level, not signature level

### WSG-012: Timing-Constant Signature Comparison
**Scenario:** Signature comparison uses constant-time algorithm
**Input:**
```json
{
  "stripe_signature": "t=1234567890,v1=abc123...",
  "payload": {...}
}
```
**Expected Output:**
- Comparison uses hash_equals() or similar
- No timing side-channel vulnerabilities

### WSG-013: Large Payload Handling
**Scenario:** Large webhook payload is processed
**Input:**
```json
{
  "id": "evt_large",
  "type": "payment_intent.succeeded",
  "data": {
    "object": {
      "id": "pi_large",
      "amount": 5000,
      "metadata": {"large_field": "<100KB string>"}
    }
  }
}
```
**Expected Output:**
- HTTP 200 OK
- Event processed normally
- Response within 5 seconds

### WSG-014: Concurrent Webhook Processing
**Scenario:** Same event arrives concurrently
**Input:**
- Two simultaneous requests with same event ID
**Expected Output:**
- Both return HTTP 200
- Only one transaction created
- Database constraint prevents duplicate

### WSG-015: Missing Payment Intent in Database
**Scenario:** Payment intent not found in local records
**Input:**
```json
{
  "id": "evt_unknown",
  "type": "payment_intent.succeeded",
  "data": {

      "amount": 5000,
      "metadata": {}
    }
  }

**Expected Output:**

- Manual review triggered

### WSG-016: Processing Error Returns 500
**Scenario:** Unexpected error during processing
**Input:**
- Valid webhook with exception during CreditService call
**Expected Output:**
- HTTP 500 Internal Server Error
- Error logged with context
- Stripe will retry webhook

## Security Considerations

1. **Never trust webhook payload** - Always verify signature
2. **Timing-constant comparison** - Use hash_equals()
3. **Log all attempts** - For audit and debugging
4. **Idempotency** - Prevent double-charges
5. **Response time** - Must respond within 5 seconds
6. **No sensitive data in logs** - Mask client secrets

## Notes for Developer

1. **Controller Skeleton Location:** `app/Http/Controllers/Api/V1/Payment/StripeWebhookController.php`
2. **Service Skeleton Location:** `app/Services/Gateway/StripeWebhookService.php`
3. **Route:** `POST /api/v1/payments/stripe/webhook`
