# TEST-34-13: AnalyticsAggregator Service Tests

## Task Reference
- **Task:** TASK-34-13
- **Specification:** SPEC-034
- **Feature:** FEAT-034 - AI Visibility Tracking (Generative Engine Optimization)

---

## Overview

Comprehensive test suite for the `AnalyticsAggregator` service that calculates mention rates, share of voice, trend analysis, and sentiment breakdowns for AI visibility tracking.

**Key Responsibilities:**
1. Period-based analytics aggregation (day, week, month)
2. Mention rate calculation per platform
3. Share of voice calculation (brand vs competitors)
4. Trend direction detection (up/down/stable)
5. Category breakdown with mention rates
6. Sentiment breakdown with average scores

class AnalyticsAggregator

### 5. Database Aggregation Examples

```php
// Use query builder for aggregation (not PHP loops)
$totalQueries = AIQueryResult::where('project_id', $projectId)
    ->whereBetween('queried_at', [$start, $end])
    ->count();

$brandMentions = AIQueryResult::where('project_id', $projectId)
    ->where('brand_mentioned', true)
    ->whereBetween('queried_at', [$start, $end])
    ->count();

// Platform-specific aggregation
$platformMentions = AIQueryResult::where('project_id', $projectId)
    ->where('platform', $platform)
    ->whereBetween('queried_at', [$start, $end])
    ->selectRaw('COUNT(*) as total, SUM(CASE WHEN brand_mentioned THEN 1 ELSE 0 END) as brand')
    ->first();

// Category grouping
$categories = AIQueryResult::where('project_id', $projectId)
    ->whereBetween('queried_at', [$start, $end])
    ->select('query_category', DB::raw('COUNT(*) as count'))
    ->groupBy('query_category')
    ->orderByDesc('count')
    ->limit($limit)
    ->get();

// Sentiment breakdown
$sentiments = AIQueryResult::where('project_id', $projectId)
    ->whereBetween('queried_at', [$start, $end])
    ->select('sentiment', DB::raw('COUNT(*) as count'), DB::raw('AVG(sentiment_score) as avg_score'))
    ->groupBy('sentiment')
    ->get();
```

### PreTester Test Design (2026-03-07 20:30 UTC)

**Test Approach:**
- Unit tests with mocked dependencies (models, facades)
- Each method tested independently with comprehensive scenarios
- Error paths tested with exception mocking
- Cache behavior tested with Cache facade mock
- Database aggregation tested with query builder mocking
- Performance tests with timing assertions

**Dependencies:**
- TASK-34-2 (Models) - Mocked in tests
- TASK-34-5 (AIVisibilityService) - Not directly used

**TDD Pattern:**
- Tests written before service implementation
- All tests will fail until service is created
- Mock interfaces define expected behavior

**Edge Cases Identified:**
- Division by zero in rate calculations
- Negative/zero queries
- Empty competitors
- Null sentiment scores
- Unicode and special characters
- XSS and SQL injection prevention
- Large data handling
- Performance requirements
- Cache stampede protection
- Concurrent requests
- Period boundary conditions
- DST transitions
- Timezone handling

**Security Considerations:**
- Project isolation enforced
- SQL injection prevention via Eloquent/parameter binding
- XSS prevention via escaping in output
- Input validation on all parameters

**Performance Notes:**
- Use database aggregation (GROUP BY, COUNT, SUM, AVG) instead of PHP loops
- Cache results for 1 hour
- Batch processing for large datasets
- Use indexes on project_id, queried_at, platform
