# TESTS Template

This folder contains automated test documentation.

## Naming Convention
`SPEC-X-Y.md` where X-Y matches the related task.

## Test File Structure

```markdown
# TESTS/SPEC-X-Y: [Feature Name] — Test Documentation

## Related
- Task: TASKS/SPEC-X-Y.md
- Specification: SPEC-X

## Test Status
- [ ] Tests designed
- [ ] Unit tests written
- [ ] Integration tests written
- [ ] E2E tests written (if applicable)
- [ ] All tests passing locally
- [ ] All tests passing in production

## Test Cases

### Test 1: [Test Name]
- **Type:** Unit/Integration/E2E
- **Description:** What is being tested
- **Preconditions:** Setup required
- **Steps:**
  1. Step 1
  2. Step 2
- **Expected Result:** What should happen
- **Edge Cases:** Boundary conditions

### Test 2: [Test Name]
...

## Test File Location
`tests/[type]/[filename].test.js`

## Notes
_Additional test context_
```

---

## Test Status & Task Status Correlation

| Task Status | Test Status |
|-------------|-------------|
| `To Write Tests` | Tests not started |
| `Tests Coverage In Progress` | Tests being written |
| `To Develop` | Tests ready, implementation pending |
| `Testing Locally` | Tests being executed locally |
| `Testing Prod` | Tests being executed in production |
