## Overview

Tests for the `CostTrackingService` that calculates and records analysis costs. For MVP, costs are estimated/notional for transparency and future monetization preparation. The service provides cost recording, calculation, user summaries, and detailed breakdowns.

## Service Interface

```php
class CostTrackingService
{
    public function __construct() {}

    /**
     * Record costs for an analysis
     */
    public function recordCost(AnalysisHistory $analysis, array $metrics = []): void;

    /**
     * Calculate cost for a tool with given metrics
     */
    public function calculateCost(string $toolName, array $metrics = []): float;

    /**
     * Get cost summary for a user
     */
    public function getUserCostSummary(int $userId, ?string $period = null): array;

    /**
     * Get detailed cost breakdown for an analysis
     */
    public function getCostBreakdown(int $analysisId): Collection;
}
```

## Notes for Developer

### Service Implementation

1. **Create Service File**: `backend/app/Services/CostTrackingService.php`

2. **Create Config File**: `backend/config/costs.php`

3. **Register Service** (optional): Add to `AppServiceProvider` if singleton needed

### MVP Cost Model

All tools are **FREE** for MVP:
- `meta_analyzer` - Free
- `heading_analyzer` - Free
- `serp_analyzer` - Free (Google CSE free tier)
- `backlink_analyzer` - Free
- `pwa_analyzer` - Free

Cost architecture supports future paid tiers.

### Key Implementation Points

1. **Transaction Safety**: Use DB transactions for multi-record operations

2. **Default Fallback**: If tool not in config, use `default_rate` (0.01)

3. **Precision**: Use `bcmath` or Laravel's `Decimal` for financial calculations

4. **Caching**: Consider caching config for performance

5. **Logging**: Log cost recording for audit trail

6. **Error Handling**: Wrap in try/catch, use custom exceptions

### Database Constraints

- `cost_units`: DECIMAL(10,4)
- `cost_amount`: DECIMAL(10,6)
- Both support high precision for micro-costs
