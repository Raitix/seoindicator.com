## Mock Strategy

### Socialite Mock
```php
use Laravel\Socialite\Facades\Socialite;
use Laravel\Socialite\Two\User as SocialiteUser;
use Mockery;

$googleUser = new SocialiteUser();
$googleUser->id = '123456789';
$googleUser->name = 'John Doe';
$googleUser->email = 'john@example.com';
$googleUser->avatar = 'https://lh3.googleusercontent.com/avatar';
$googleUser->token = 'ya29.a0_token';
$googleUser->refreshToken = '1//refresh_token';
$googleUser->expiresIn = 3600;
$googleUser->user = ['email_verified' => true];

$mockProvider = Mockery::mock('Laravel\Socialite\Two\GoogleProvider');
$mockProvider->shouldReceive('stateless')->andReturnSelf();
$mockProvider->shouldReceive('user')->andReturn($googleUser);

Socialite::shouldReceive('driver')
    ->with('google')
    ->andReturn($mockProvider);
```

### State Extraction Helper
```php
protected function extractStateFromRedirectUrl(string $url): string
{
    parse_str(parse_url($url, PHP_URL_QUERY), $params);
    return $params['state'] ?? '';
}
```

## Notes for Developer

1. **Test Isolation:**
   - Use RefreshDatabase trait for clean state
   - Clear cache before/after tests affecting OAuth state
   - Mock Socialite to avoid actual Google API calls

2. **State Testing:**
   - State must be 40 characters
   - State must be stored in cache before redirect
   - State must be consumed (removed) after callback
   - State must have 10-minute TTL

3. **Account Linking:**
   - Email matching is case-insensitive
   - Avatar only updated if user doesn't have one
   - Password preserved when linking OAuth to existing account
   - Email auto-verified only if Google confirms email is verified

4. **Error Handling:**
   - All errors must have consistent structure
   - No stack traces in production mode
   - User-friendly error messages
   - Detailed errors logged for debugging
