## Overview

Integration tests for the complete Google OAuth flow, testing end-to-end scenarios including HTTP requests, database changes, and authentication state.

These tests verify the interaction between:
- `GoogleAuthController` (HTTP endpoints)
- `GoogleOAuthService` (OAuth logic)
- `User` and `SocialAccount` models (database)
- Laravel Sanctum (authentication)

## Test Scenarios

### Full OAuth Flow Tests (FLOW)

| ID | Scenario | Input | Expected Output |
|----|----------|-------|-----------------|
| FLOW-001 | Complete OAuth flow creates new user | Valid OAuth callback | User + SocialAccount created, email verified, token returned |
| FLOW-002 | Complete OAuth flow logs in existing user | Existing user callback | Returns existing user, is_new_user=false |
| FLOW-003 | OAuth flow links account by email | Same email, new Google ID | Links Google account to existing user |
| FLOW-004 | Multiple OAuth requests generate unique states | 5 redirect requests | 5 unique states, all cached |
| FLOW-005 | Token is valid for authenticated requests | OAuth token on /api/v1/auth/user | Returns user data |

### State Management Tests (STATE)

| ID | Scenario | Input | Expected Output |
|----|----------|-------|-----------------|
| STATE-001 | State consumed after successful callback | Valid callback | State removed from cache |
| STATE-002 | State cannot be reused | Second callback with same state | 400 error, invalid_state |
| STATE-003 | Expired state is rejected | 11+ minute old state | 400 error, invalid_state |
| STATE-004 | State validation prevents CSRF | Attacker's state | 400 error, legitimate state untouched |

### Database State Tests (DB)

| ID | Scenario | Input | Expected Output |
|----|----------|-------|-----------------|
| DB-001 | User created with correct attributes | New user callback | Correct name, email, avatar, verified, null password |
| DB-002 | Social account created with encrypted tokens | Tokens in callback | Tokens encrypted at rest, decrypted via model |
| DB-003 | Existing social account tokens updated | Existing user callback | Tokens updated to new values |
| DB-004 | Multiple providers for same user | Existing GitHub + new Google | Two social accounts linked |

## Notes for Developer

1. **Integration vs Unit Tests**: These tests use real HTTP requests and database operations. Unit tests mock the service; these tests verify the integration.

2. **State Management**: Each test generates fresh states via HTTP calls to ensure isolation.

3. **Token Verification**: FLOW-005 verifies tokens work with Sanctum by making an authenticated request.

4. **Rate Limiting**: Tests verify rate limiting on callback (5/min) but not on redirect endpoint.

5. **Error Scenarios**: Tests verify both error responses and that no database changes occur on failure.
