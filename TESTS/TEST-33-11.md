## Notes for Developer

1. **Sorting Implementation**: Issues should be sorted client-side by severity (Critical → Warning → Info) before rendering. Secondary sort by category.

2. **Expandable State**: Each issue should maintain its own expanded/collapsed state. Consider using a Set of expanded IDs or individual state per item.

3. **Accessibility First**: All interactive elements must be keyboard-accessible. Use `aria-expanded` for expandable items, `aria-labelledby` for the container.

4. **Performance**: For large issue lists (50+), consider virtualization. The component should handle up to 100 issues without performance degradation.

5. **Partial View Logic**:
   - When `isPartial=true`, show only first 5 issues
   - Show "View Full Report" button with link to `/audit/{auditHash}`
   - Show remaining count: "+X more issues"

6. **Badge Styling**:
   - Critical: Red background (destructive variant)
   - Warning: Yellow/amber background (warning variant)
   - Info: Blue background (secondary variant)
   - Categories: Use distinct colors for each category

7. **Truncation**:
   - Titles: Truncate to ~60 characters with ellipsis
   - Descriptions (collapsed): Truncate to ~100 characters
   - Full description visible when expanded
