## Notes for Developer

### Controller Structure
```
app/Http/Controllers/Api/V1/Admin/HealthController.php
├── overview()  - GET /api/v1/admin/health/overview
├── queues()    - GET /api/v1/admin/health/queues
├── database()  - GET /api/v1/admin/health/database
└── alerts()    - GET /api/v1/admin/health/alerts
```

### Routes (routes/api.php)
```php
Route::middleware(['auth:sanctum', 'admin', 'throttle:120,1'])
    ->prefix('api/v1/admin/health')
    ->group(function () {
        Route::get('/overview', [HealthController::class, 'overview']);
        Route::get('/queues', [HealthController::class, 'queues']);
        Route::get('/database', [HealthController::class, 'database']);
        Route::get('/alerts', [HealthController::class, 'alerts']);
    });
```

### Service Dependencies
- `HealthCheckService` (TASK-27-11) - Inject into overview method
- `QueueMonitoringService` (TASK-27-12) - Inject into queues method
- Use Laravel's built-in `DB` facade for database metrics
- Create `AlertService` or use simple config/cache for alerts

### Mocking Strategy
Since dependencies are blocked, the Developer should:
1. Create interfaces for services
2. Use Laravel's built-in DB/Cache/Queue facades for basic functionality
3. Implement stub services that return default data
4. Tests will pass with mocked implementations

### Rate Limiting
The 120 req/min rate limit should be implemented via:
```php
Route::middleware(['throttle:120,1'])
```

### Performance Optimization
For 30-second polling:
- Cache health overview for 10-15 seconds
- Use lightweight queries (no heavy aggregations)
- Return partial data if services unavailable
