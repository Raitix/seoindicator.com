## Notes for Developer

1. **Component Structure:**
   - Use React Query for data fetching with URL state sync
   - Implement skeleton loading states for all sections
   - Use URL params for filter/pagination state (shareable links)

2. **API Integration:**
   - Endpoint: `GET /api/v1/analyses`
   - Query params: `page`, `perPage`, `tool`, `status`, `from`, `to`
   - Delete: `DELETE /api/v1/analyses/{id}`
   - Detail: `GET /api/v1/analyses/{id}`
   - See SPEC-025 for full API specification

3. **Filter Implementation:**
   - Debounce filter changes (300ms)
   - Sync filters with URL params
   - Reset to page 1 when filters change
   - Preserve filters when paginating

4. **Responsive Design:**
   - Desktop: Full table with all columns
   - Tablet: Condensed table, fewer columns
   - Mobile: Card list layout
   - Use Tailwind responsive classes

5. **Accessibility:**
   - Proper heading hierarchy (H1 for page title)
   - ARIA labels on table and filters
   - Keyboard navigation for all controls
   - Focus trap in modal dialogs
   - Screen reader friendly status badges

6. **Error Handling:**
   - Graceful degradation for partial data
   - Retry functionality for failed loads
   - User-friendly error messages
   - Redirect to login on 401

7. **Performance:**
   - Virtualization for large datasets (optional)
   - Debounced filter API calls
   - Proper cleanup on unmount
   - Memoize expensive calculations

8. **Security:**
   - Sanitize all user inputs
   - Escape HTML in displayed data
   - CSRF token for delete requests
   - IDOR protection on backend
