## Schema Definition

### ai_analysis_requests Table

```sql
CREATE TABLE ai_analysis_requests (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    analysis_id BIGINT UNSIGNED NOT NULL,
    model VARCHAR(100) NOT NULL,
    prompt_tokens INT UNSIGNED NULL,
    response_tokens INT UNSIGNED NULL,
    total_tokens INT UNSIGNED NULL,
    latency_ms INT UNSIGNED NULL,
    truncation_strategies JSON NULL,
    request_hash VARCHAR(64) NULL,
    status ENUM('pending', 'completed', 'failed') DEFAULT 'pending',
    error_message TEXT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (analysis_id) REFERENCES seo_analyses(id) ON DELETE CASCADE,
    INDEX idx_analysis_status (analysis_id, status),
    INDEX idx_model (model),
    INDEX idx_request_hash (request_hash),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### seo_analyses New Columns

```sql
ALTER TABLE seo_analyses 
ADD COLUMN ai_model VARCHAR(100) NULL COMMENT 'AI model used for analysis',
ADD COLUMN prompt_tokens INT UNSIGNED NULL COMMENT 'Tokens sent to AI',
ADD COLUMN response_tokens INT UNSIGNED NULL COMMENT 'Tokens received from AI',
ADD COLUMN total_tokens INT UNSIGNED NULL COMMENT 'Total tokens used',
ADD COLUMN truncation_applied JSON NULL COMMENT 'Truncation strategies applied',
ADD COLUMN overall_summary TEXT NULL COMMENT 'AI-generated overall summary',
ADD COLUMN category_scores JSON NULL COMMENT 'Category-level scores',
ADD COLUMN ai_request_id BIGINT UNSIGNED NULL COMMENT 'FK to ai_analysis_requests',
ADD INDEX idx_ai_model (ai_model),
ADD INDEX idx_ai_request (ai_request_id);
```

## Notes for Developer

### Implementation Order
1. Create first migration file (ai_analysis_requests table)
2. Create second migration file (seo_analyses columns)
3. Run migrations: `php artisan migrate`
4. Run tests to verify

### Backward Compatibility
- All new columns are **nullable**
- Existing analyses remain valid without AI data
- Old records can be re-analyzed with unified prompt
- No data migration required

### Foreign Key Considerations
- FK on `analysis_id` with CASCADE DELETE
- When seo_analysis is deleted, related ai_analysis_requests are auto-deleted
- Prevents orphaned records

### Index Strategy
- Composite index `(analysis_id, status)` for filtering requests by analysis and status
- Single indexes on `model`, `request_hash`, `created_at` for common query patterns
- Index on `ai_model` and `ai_request_id` in seo_analyses for JOIN optimization

### JSON Column Usage

**truncation_strategies example:**

**category_scores example:**
