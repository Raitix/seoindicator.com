# TESTS: TASK-12-12 — Production API Routes

## Overview
Tests for verifying `/api/health` and GSC endpoints resolve correctly on production.

**Issue Identified:** Production API routes returning 404 due to incorrect `.htaccess` routing configuration.

---

## Root Cause Analysis

### Problem
The root `.htaccess` file contains:
```apache
RewriteRule ^api/(.*)$ backend/public/index.php [L,QSA]
```

This rule captures the path **after** `/api/` and passes it to Laravel, but Laravel's `api.php` routes already expect the `/api/` prefix.

**Example:**
- Request: `GET /api/health`
- After rewrite, Laravel sees: `REQUEST_URI = /health`
- Laravel route `/api/health` doesn't match → **404**

### Solution
Update `.htaccess` to preserve the full request URI:
```apache
# Correct approach - preserve full URI
RewriteCond %{REQUEST_URI} ^/api/ [NC]
RewriteRule ^ backend/public/index.php [L]
```

## Routing Fix Required

**File:** `.htaccess` (project root)

**Current (broken):**
```apache
RewriteRule ^api/(.*)$ backend/public/index.php [L,QSA]
```

**Recommended Fix:**
```apache
# Route API requests to Laravel backend
RewriteCond %{REQUEST_URI} ^/api/ [NC]
RewriteRule ^ backend/public/index.php [L]
```

This preserves the full `REQUEST_URI` so Laravel sees `/api/health` instead of just `/health`.
