## Description
Security remediation for exposed secrets and deployment hardening. Covers APP_KEY rotation, env secret hygiene, deployment endpoint rate limiting/logging, and OAuth production configuration review.

## User Story
As a system owner, I want all secrets removed from the repo and sensitive endpoints protected so that deployments and OAuth are safe to run in production.

## Business Impact
### Revenue
Prevents security incidents that could halt operations or require emergency remediation.

### User Behavior
Ensures authentication and integrations remain trustworthy after deployment.

### Retention
Reduces risk of outages or data exposure that would cause churn.

### Legal & Compliance
Reduces risk of credential leakage and improper data handling.

### Complexity & Cost
Requires careful secret rotation and git history cleanup; no paid tools.

## Acceptance Criteria
- [ ] No secrets present in repository or git history
- [ ] Secrets stored only in environment variables / GitHub Secrets
- [ ] Deploy endpoints rate limited and logged
- [ ] OAuth production configuration reviewed and validated
