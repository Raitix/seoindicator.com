# FEATURES Template

This folder contains feature definitions.

## Naming Convention
`FEAT-X.md` where X is a sequential number.

## Feature File Structure

```markdown
# FEAT-X: [Feature Name]

## STATUS
`New Feature` | `Cancelled`

## PRIORITY
`High` | `Medium` | `Low`

## RISK
`Low` | `Medium` | `High`

## Description
_Brief description of the feature_

## User Story
As a [user type], I want [goal] so that [benefit].

## Business Impact
### Revenue
_How does this generate revenue or reduce costs?_

### User Behavior
_How does this affect user engagement and workflow?_

### Retention
_How does this increase user retention?_

### Legal & Compliance
_Are there regulatory, privacy, or legal considerations?_

### Complexity & Cost
_How can we minimize implementation complexity and ongoing costs?_

## Acceptance Criteria
- [ ] Criterion 1
- [ ] Criterion 2

## Related
- Specification: SPEC-X
- Tasks: SPEC-X-1, SPEC-X-2, ...

## Notes
_Additional context or decisions_

---

## Comments
_Agent communication log_

### [YYYY-MM-DD HH:MM] Agent: [Name]
_[Comment or note from agent]_

### [YYYY-MM-DD HH:MM] Agent: [Name]
_[Comment or note from agent]_
```

---

## Valid Status Values & Agent Actions

| Status | Who | Action |
|--------|-----|--------|
| `New Feature` | Innovator | **Creates** feature with this status |
| `New Feature` | Architect | **Picks up** for specification |
| `Cancelled` | Any agent | Sets with documented reason |

---

## Communication
Agents leave comments in the **Comments** section for handoff notes, decisions, and questions.

---

## Workflow

```
Innovator creates FEAT-X ("New Feature")
         ↓
Architect picks up ("New Feature")
         ↓
Architect creates SPEC-X
```
